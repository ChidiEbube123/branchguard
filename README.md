# BranchGuard-AI

**Autonomous Parallel SWE Agent & Sandbox Debugger**
Nebius x NVIDIA Global AI Hackathon — Coding & Agentic Engineering Track

BranchGuard-AI turns a failing GitHub Actions build into a verified,
self-healing pull request. It fans a CI failure out into three parallel
bug-fix hypotheses generated by **NVIDIA Nemotron 3** (served on **Nebius
Token Factory**), tests each one in an isolated, git-like forked
**Nebius Token Factory Sandbox**, picks the branch that passes with the
lowest resource footprint, and opens the winning PR automatically.

## Architecture

```
GitHub Webhook (workflow_run failure)
        │
        ▼
Django Backend API  (webhook ingestion + DB event logging)
        │
        ▼
Celery Worker (async task pipeline)
        │
    ┌───┴────────────────────────┐
    ▼                            ▼
Nebius Sandboxes API      Nebius Model API
(fork branches, run       (NVIDIA Nemotron 3 —
 tests, verify patches)    generates 3 fix hypotheses)
```

## Setup

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env   # then fill in NEBIUS_API_KEY, GITHUB_* values

python manage.py migrate
python manage.py createsuperuser   # optional, for /admin/
```

## Running locally

You need Redis running for Celery:

```bash
redis-server &

# Terminal 1 — Django dev server
python manage.py runserver

# Terminal 2 — Celery worker
celery -A branchguard worker -l info --concurrency=4
```

## Wiring up the GitHub webhook

1. In your repo's Settings → Webhooks, add:
   `https://<your-host>/api/webhooks/github/`
2. Content type: `application/json`
3. Events: **Workflow runs**
4. Secret: same value as `GITHUB_WEBHOOK_SECRET` in `.env`

When a `workflow_run` event arrives with `status=completed` and
`conclusion=failure`, BranchGuard creates an `AnalysisRun` and enqueues
`process_ci_failure_task`, which:

1. Summarizes the root cause with Nemotron 3.
2. Asks Nemotron 3 for 3 distinct, structured fix hypotheses (JSON, with
   unified diffs).
3. Boots a base Nebius Sandbox at the failing commit, then forks it into 3
   parallel branches (git-like branching).
4. Applies each patch and runs the test suite concurrently across all 3
   branches, capturing stdout/stderr, execution time, and memory usage.
5. Picks the branch that passed with the lowest resource usage, opens a PR
   with a full benchmark table, and tears down every sandbox branch.

## Dashboard API

- `GET /api/runs/` — list of analysis runs (filter with `?status=RUNNING`)
- `GET /api/runs/{id}/` — full run detail, including every sandbox branch,
  its diff, test status, and resource metrics
- `GET /api/runs/{id}/branches/` — just the branch benchmark comparison
- `/admin/` — Django admin for manual inspection during judging

## Notes for judges

Every call into Nebius Token Factory (both the Nemotron 3 model endpoint
and the Sandboxes REST API) is explicitly marked in `agents/nebius_client.py`
with `# === NEBIUS TOKEN FACTORY CALL ... ===` comments for easy auditing.

`agents/github_client.py`'s patch-application step (`_commit_patch`) is a
placeholder — a production build would apply the unified diff via the Git
Data API's tree/blob endpoints or a temporary local checkout + push.
